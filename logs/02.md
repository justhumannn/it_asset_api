## 실행한 검사

- 명령: `python -m pytest tests checks/check_availability_contract.py -v`
- 실행한 검사 수: **22개** (새 테스트 15 + 기존 tests 3 + checks 4)
- 핵심 출력: `22 passed, 1 warning in 0.36s` (warning은 httpx/starlette deprecation, 결과와 무관)
- 추가한 검사(`tests/test_department_availability.py`)가 확인하는 정책: 위 표 1~12
- 기존 검사도 통과했는가: 예 — `tests/test_equipment.py` 3개, `checks/check_availability_contract.py` 4개 모두 PASSED, 기존 검사 파일은 수정하지 않음
- 잘못된 구현을 잡는지 확인: 일반 부서 조건을 일시적으로 `quantity <= available`(모든 부서를 IT처럼)로 바꿔 실행 → `FAILED test_department_policy[general-1-3-3-False]`, `1 failed, 21 passed`. 원래 코드로 되돌린 뒤 `22 passed`
- 아직 검사하지 못한 조건: 재고 1인 장비에서의 일반 부서(항상 불가) — 장비 데이터 변경 금지로 실제 데이터 사례 없음. `department=it&department=general`처럼 중복 전달 시 동작. 대소문자 무시 여부는 정책 미확정이라 허용값 그대로(`IT`는 거절)로 구현 — 담당자 확인 필요.

## diff 확인

- 부서 판단을 처리한 위치: `app/services/equipment_service.py` `check_availability()` — `department == "general"`이면 `quantity <= available - 1`, 그 외(it/생략)는 `quantity <= available`
- 부서 입력 검증 위치: `app/routers/equipment.py` — `department: Literal["it", "general"] | None = Query(default=None)`. 허용값 외 입력은 FastAPI가 422로 거절, 생략 시 `None`
- 변경 파일과 이유 (`git diff --stat`):
  - `app/routers/equipment.py | 10 ++++++++--` — 선택적 쿼리 매개변수 추가, 서비스에 전달
  - `app/services/equipment_service.py | 9 +++++++--` — 부서별 판단
  - `tests/test_department_availability.py` (새 파일) — 새 정책 검사, 직접 열어 확인
  - `logs/02.md` — 이 기록
- 변경하지 않은 것: `app/data.py`, `app/schemas.py`(응답 필드 그대로), `tests/test_equipment.py`, `checks/`, `requirements.txt`
